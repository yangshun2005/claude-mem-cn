# Claude-Mem 速查表

*一页纸掌握 Claude-Mem 全部要点。无需写代码。Hack 时开着它。*

---

## 1. 它是什么（10 秒读懂）

**Claude-Mem = AI 编程 Agent 的记忆层。**
第二个 Agent 观察你的主 Agent 工作，把重要内容写成结构化笔记，下次会话时交还给它。你的 Agent 开局就有记忆，而不是从零开始。

开源。10 万+ 开发者。`github.com/thedotmack/claude-mem`

---

## 2. 为什么需要它（失忆的三重代价）

| 没有记忆 | 有 Claude-Mem |
|---|---|
| 每次会话从零开始——Agent 重读代码库 | 会话开局就有上次的时间线 |
| 重读 = Token = 花钱 | 标题优先召回：大量工作压缩成极小索引（典型启动上下文报告节省约 99%） |
| "当初为什么这么做？"——没人记下来 | 决策*连同理由*一起记录，永久可搜索 |

---

## 3. 两个 Agent

| | 主 Agent（构建者） | 观察者 Agent（记录者） |
|---|---|---|
| **做什么** | 读、改、跑命令、和你对话 | 观察。写笔记。从不和你对话。 |
| **看到什么** | 你的提示词、文件、结果 | 构建者的*每一次工具调用*及其结果 |
| **决定什么** | 构建什么 | **"这值得记一笔吗？"**——大多数时候：不值得 |
| **速度** | 从不等待观察者 | 后台工作 |

关键规则：Claude-Mem **从外部观察**。它从不改变主 Agent 的行为。即使它消失了，构建者照常工作——只是事后没有记忆。

---

## 4. 如何接入（生命周期节点）

| 节点 | Claude-Mem 做什么 |
|---|---|
| **会话开始** | 注入时间线：最近的笔记标题、ID、时间、分类图标。"热启动"。 |
| **每次工具调用后** | 把动作 + 结果交给观察者 → 观察者决定记 / 不记 |
| **轮次或会话结束** | 观察者写一段简短进度摘要：当前进展、下一步 |

---

## 5. 笔记的结构（"观察记录"）

每条笔记结构相同。记住它——这是系统的核心。

| 字段 | 是什么 | 经验法则 |
|---|---|---|
| **标题** | 一行：发生了什么 | 未来的 Agent 通常*只*读这个。让它承载全部含义。 |
| **副标题** | 再一行上下文 | 系统的哪个部分、什么情况 |
| **事实** | 约 3 条**单句要点**（"语义块"） | 每句必须*脱离上下文*也能独立理解 |
| **叙述** | 一小段：故事、原因 | 需要全貌时使用 |
| **分类（类型）** | 模式列表中的一个标签 | 如 bugfix · feature · refactor · change · discovery · decision |
| **标签（概念）** | 可复用的知识标签 | 如 how-it-works · why-it-exists · what-changed · problem-solution · gotcha · pattern · trade-off |
| **文件** | 读取 / 修改 | 下次从哪里跳入 |
| **时间戳** | 自动 | 时间线的基础 |

示例（大白话）：

> 🔴 **bugfix** · 下午 3:48 — **修复了过期会话 Cookie 导致的登录重定向循环**
> • 仅当 Cookie 超过 24 小时才会出现循环。• 修复方式：重定向前清除 Cookie。• 逻辑在认证中间件里，不在登录页。
> *叙述：看起来像前端路由 bug；实际原因在服务端。* 标签：problem-solution, gotcha

## 6. 笔记存在哪里

- 本地数据库 + 语义感知搜索索引，位于你机器上的 **`~/.claude-mem`**。
- 除了调用负责观察的 AI 模型外，数据不外发。本地安装仅在注册时联系 cmem.ai 一次以生成登录链接；不会向 cmem.ai 发送其他内容。
- 可选：**CMEM Pro** 跨机器云同步（Hack 参与者：免费 30 天，在 cmem.ai 使用优惠码 **FASTHACK30**）。
- 本地**查看器**网页实时显示笔记落库，可浏览、可搜索。

## 7. 笔记如何召回——从最便宜开始

```
第 1 层  时间线    会话开始时自动    仅标题 + ID          （便宜，约数百 Token）
第 2 层  按 ID 获取  按需            事实 + 叙述          （只为所需付费）
第 3 层  搜索      较旧 / 在其他地方  按语义、关键词、      （先标题，再获取）
                                   分类、日期、项目
```

口诀：**标题优先，细节按需。** 绝不一次性倾倒全部。

## 8. 模式——观察者的岗位说明（可替换！）

**模式**是一个纯配置文件，设定：

1. **观察者是谁**（软件工程师的书记员？取证分析师？学习伙伴？）
2. **笔记分类**（bugfix/feature/… 或 entity/relationship/timeline-event/evidence/anomaly/conclusion 或 action-goal/state-change/error …）
3. 该领域的**标签**
4. **语言**（已内置 30+ 种：`code--es`、`code--ja`、`code--ar`、…）

同一套机制，不同的岗位说明 → 可观察**任何东西**：

| 模式设想 | 观察者关注什么 |
|---|---|
| code（默认） | bugfix、feature、决策、发现 |
| code--chill | 只记重新发现会很痛苦的事 |
| email-investigation | 人物、组织、关系、时间线事件、异常 |
| law-study | 案例、规则、考试相关要点 |
| meme-tokens | 拉盘信号、交易模式 |
| robot monitoring | 目标、状态变化、错误 |
| **你的模式** | 白板照片 · 会议记录 · 聊天日志 · 支持工单 · 日志 · 截图 |

无需手写即可创建：**`/mode-creator`**（访谈你，然后编写 + 安装 + 激活该模式）。

**任意数据输入，任意模式输出。**

## 9. 可用来构建的积木

| 积木 | 提供什么 |
|---|---|
| **时间线** | 按时间排序的带 ID 笔记；锚定一条，读其前后 |
| **搜索** | 语义 + 关键词，按项目 / 分类 / 日期过滤 |
| **技能**（CLI 形态，文本进 → 文本出） | mem-search · timeline-report · knowledge-agent · mode-creator · how-it-works · learn-codebase · make-plan / do |
| **实时观察** | Agent 工作时笔记*实时*落库 → 可触发反应 |
| **会话摘要** | 每次会话结束时的交接笔记 |

## 10. 五分钟上手

1. `npx claude-mem install`
2. 在一个会话中工作（观察者开始记笔记）
3. 在同一项目中开**第二个**会话 → 顶部出现时间线。这就是记忆。*（第一个会话播种；第二个会话才感受得到。）*
4. 问"X 是不是已经修过了？" → Agent 使用搜索
5. 打开查看器，看笔记实时落库
6. `/mode-creator` → 把观察者对准非代码的东西

---

## 11. $1,000 记忆奖——七个方向

1. **热启动**——即时上下文，无需十轮重新摸索
2. **基于时间线构建**——把时间线 + 搜索作为你的召回层
3. **给技能一张脸**——UI/UX，让记忆可见、可操控、可分享
4. **构建集成**——编辑器、CI、聊天应用、其他 Agent 框架
5. **任意摄入，任意查找**——图片、转录、日志、工单 + 自定义模式
6. **见即触发**——实时对观察记录做出反应
7. **记忆即速度**——更少 Token、更少轮次、更少秒数

与总榜第 1–3 名分开评审（可同时获奖）。**加分项：真的会有人用吗？**

## 12. 词汇表（大白话）

- **观察者**——负责记笔记的第二个 Agent
- **观察记录**——一条笔记（标题、事实、叙述、分类、标签、文件、时间）
- **工具调用**——主 Agent 的一次动作（读 / 改 / 跑 / 搜）
- **时间线**——会话开始时注入的按时间排序的笔记标题列表
- **模式**——观察者的岗位说明（角色、分类、标签、语言）
- **技能**——Agent 可运行的小型可复用辅助命令
- **会话摘要**——会话结束时的"当前进展 / 下一步"笔记
- **热启动**——开局即知前情的会话
