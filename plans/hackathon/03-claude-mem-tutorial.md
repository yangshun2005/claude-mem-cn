# Claude-Mem 教程：一次上手，从零到"它记住了"

*面向黑客松开发者的分步指南。无需前置知识。每一步都告诉你做什么、会看到什么、意味着什么。*

---

## 开始之前

你需要一个能接入 Claude-Mem 的 AI 编码代理（主要是 Claude Code，其他代理也有集成）、一个终端，以及大约十五分钟。就这些。其余所需组件 Claude-Mem 会自行安装。

动手之前先建立一个心智模型：Claude-Mem 是**第二个代理，它观察你的第一个代理并做笔记**。我们将安装它、观察它做笔记、看笔记如何回传、搜索笔记，然后改变它观察的对象。共五个阶段。

---

## 阶段 1 — 安装（2 分钟）

**执行：**

```
npx claude-mem install
```

**你会看到：** 安装程序会配置插件和一个小型后台服务，并检查它依赖的两个辅助工具（一个快速 JavaScript 运行时，以及用于搜索索引的 Python 工具管理器）是否存在——不存在则安装。

**意味着：** 从现在起，该代理中的每次编码会话都会被观察。你没有改变代理的任何工作方式，只是在房间里放了一个记录员。

---

## 阶段 2 — 第一次被观察的会话（5 分钟）

**执行：** 在任意项目中启动一次正常的编码会话。做几件真实的事——读几个文件、做个小修改、运行一条命令、修点东西。让代理给你解释部分代码。

**你会看到：** 没有任何不同。这正是重点。主代理的行为与之前完全一致。

**幕后发生的事：** 代理的每个动作——每次读取、编辑、命令——都交给了观察者。对每个动作，观察者都会问"值得记一笔吗？"，对有意思的动作则写一条笔记：标题、副标题、几条单句事实、一段简短叙述、一个分类（bugfix / feature / discovery / decision / …）、一些标签，以及涉及的文件。

**可选——实时观看：** 在浏览器中打开本地查看器（安装输出会告诉你地址）。工作时把它放在第二块屏幕上，就能看到笔记随代理操作实时出现。这是理解 Claude-Mem 在做什么的最佳方式。

---

## 阶段 3 — 热启动：看记忆回传（2 分钟）

**执行：** 结束会话。在**同一**项目中启动一个**新**会话。

**你会看到：** 新会话顶部、你还没输入任何内容时，会出现一个紧凑的区块，像这样：

```
# [claude-mem] recent context
Mode: Code Development (code)

Legend: 🎯session 🔴bugfix 🟣feature 🔄refactor ✅change 🔵discovery ⚖️decision

ID      TIME   TYPE  TITLE
110958  12:21p 🟣    Created shared attribution module with centralised constants
110962  12:27p 🔵    Merge conflict in mcp-server when combining two branches
110969  12:30p 🟣    Branch passes full test suite: 2685 pass, 0 fail
...
Stats: 50 obs (17,530t read) | 1,324,849t work | 99% savings
```

**意味着：** 这就是**时间线**——最近发生之事的标题，每条带一个 ID。代理一眼就能读完。统计行用一行概括了全部价值：五十条笔记，读取约一万七千 token，代表超过一百万 token 的实际工作。代理现在以重做这些工作约 1% 的成本，知道了上次发生了什么。

项目中的第一次会话为记忆播种，第二次才是你真正感受到它的时候。

**试试这个：** 用平实的语言问代理上次会话你做过的事。"我们之前对认证流程改了什么？"看它从时间线作答——如果需要更多信息，它会按 ID 获取笔记详情。

---

## 阶段 4 — 搜索过去（3 分钟）

时间线只显示最近的笔记。更早的全都还在——你只需开口问。

**执行：** 问一个"我们是不是已经……"的问题。"我们是不是已经修过重定向循环了？""上周我们是怎么搭建测试数据库的？""关于缓存我们做了什么决定？"

**你会看到：** 代理使用 memory-search 技能。它遵循一个三步模式，你在 Claude-Mem 中到处都会见到：

1. **搜索** → 返回一张带 ID 的标题表（成本低）
2. 围绕感兴趣的结果看**时间线** → 它前后发生了什么
3. **按 ID 获取** → 只取真正重要笔记的完整事实 + 叙述

**意味着：** 代理从不把整个笔记本倒进上下文。它先浏览标题、缩小范围，然后只读所需内容。这种纪律——先看标题，按需取详情——正是笔记本增长时记忆仍保持低成本的原因。

**你也可以搜索：** 查看器有搜索框。试着搜一个*概念*而非精确短语（"那个 cookie 的东西"）——索引理解语义，不只是字面。

---

## 阶段 5 — 改变观察者的观察对象（5 分钟）

到目前为止都假设观察者在观察代码。现在让我们把它指向别的东西。

**思路：** 观察者的职责描述是一个**模式**——一个纯配置文件，设定观察者是谁、有哪些笔记分类、有哪些标签、用什么语言书写。换掉模式，同一套机制就能观察完全不同的东西。

**执行：**

```
/mode-creator
```

**你会看到：** 一场访谈。它会问你观察什么（代码库？邮件导出？会议记录？白板照片？机器人遥测？）、什么类型的事重要、分类应该是什么。然后它写出模式文件，安装到 `~/.claude-mem/modes/`，激活它，重启后台服务，并在启动上下文中显示新模式名称。

**试试其中之一：**

- **白板照片。** 模式："你是建筑师的助手。记录你在白板上看到的设计决策、未决问题和负责人。"然后让代理打开一张白板照片，观察笔记。
- **会议记录。** 模式："记录决策、带负责人的行动项和截止日期。"粘贴或打开一份记录，观察笔记。
- **对话 / 聊天导出。** 模式参照 email-investigation：实体、关系、时间线事件、异常。打开导出文件，观察笔记。

**意味着：** 代理能读的任何东西，观察者都能做笔记——模式决定什么算"值得记一笔"。任意数据输入，任意模式输出。

**可供参考的现成模式：** code（默认）、code--chill（只记难以重新发现的东西）、30+ 语言变体、email-investigation、law-study、meme-tokens，以及某人为自己项目构建的机器人监控模式。

---

## 阶段 6 — 可以在此基础上构建什么（阅读，非动手）

现在你已感受过这个循环，以下是黑客松中可以抓住的把手：

- **时间线** — 按时间排序、带 ID 的笔记。锚定一条，读它周围。用作检索层。
- **搜索** — 语义 + 关键词，按项目 / 分类 / 日期过滤。
- **技能** — 仓库中的小型文本输入/文本输出辅助工具（mem-search、timeline-report、knowledge-agent、mode-creator、how-it-works、learn-codebase、make-plan/do）。CLI 形态意味着易于包装进 UI、编辑器、聊天应用、CI 任务。
- **实时观察** — 代理工作时笔记实时落地。模式出现 → 触发某事。
- **会话摘要** — 会话结束时的"我们在哪 / 下一步做什么"交接。
- **模式** — 面向任意数据类型的自定义观察者职责描述。

七个奖项方向直接对应这些：热启动 · 基于时间线构建 · 给技能一个界面 · 构建集成 · 摄入任何数据 · 对所见触发 · 把记忆当作速度优势。

---

## 一句话排障

- **看不到时间线？** 它在项目中的*第二次*会话才启动。（或运行 `/learn-codebase` 一次性预加载仓库。）
- **想确认当前激活的模式？** 就是启动上下文顶部的 `Mode:` 行。
- **想实时看笔记？** 打开查看器。
- **数据在哪？** 你机器上的 `~/.claude-mem`。卸载会干净移除。

---

## 回顾

1. 安装 → 记录员加入房间。
2. 工作 → 每个动作交给观察者；有意思的变成结构化笔记。
3. 新会话 → 时间线回传：先看标题，比重做工作便宜约 99%。
4. 问"我们是不是已经……" → 搜索、时间线、按 ID 获取。
5. `/mode-creator` → 把观察者指向照片、记录、对话、任何东西。
6. 基于时间线 / 搜索 / 技能 / 实时笔记 / 摘要 / 模式构建。
