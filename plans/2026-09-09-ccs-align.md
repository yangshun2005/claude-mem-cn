## 主要目标

**常驻 CCS Align 席位能与本地 Claude-Mem worker 通信，通过现有 search → timeline → get_observations 阶梯拉取观察记录，并用 grab → append → replace（若原缓存不可写则仅追加）落入席位自有的中间缓存 — 不交付上下文编译器，不删除历史，不写 Grok `profile.md`。**

以下所有内容均以此句为衡量标准。若任务不能推动本机从“日记与 Grok 日志是两座孤岛”走向“Align 席位可重建的单一可审计中间缓存”，则不属于本计划。

## 一段话说明问题

Claude-Mem 已有可信的情景流（`search` → `timeline` → `get_observations`），且自 #3931 起，可将关键事实*推送*到 LFG/Orifice 月度日志。本机**缺少**的是 Cascading Context Sheet *运行时*：一个位于日记与编译提示之间的位置，观察记录可在此抓取、追加、替换、后续排除 — 外加对 house → project → seat 规则的周期性检查，防止叶子副本静默遮蔽级联。完整的 brainbeat / 上下文编译器是未来工作（论文脚手架已明说）。CCS Align 是**过渡席位**：单一职责，每小时，从文档复制，失败即关闭。

## 约束性规则

1. **是席位，不是全局视角。** CCS Align 是 Worker Watch 形态的常驻席位（每小时看板）。它不负责本机优先级、招聘或重新设计记忆。Prioritizer 负责这些。
2. **从现有 API 复制。** 渐进式披露和 #3931 的原子追加已在树内。不要发明 `compileAwareness()`、`brainbeatPush()`、`excludeObservation()` 或 `.cas` 解析器。
3. **历史仅追加。** 排除标记过滤*编译后*的感知。它们不 `DELETE /api/observation/:id`，也不重写 SQLite 行。Graphiti 式失效；绝不 A-MEM 重写（[Memory dig findings](https://app.notion.com/p/3d3771da7f4d8139a2e8fd3a3c9ceb05)）。
4. **不二次写入 LFG/Orifice 日志。** #3931 已向 `agents/<id>/memory/log/YYYY-MM.md` 追加 `- YYYY-MM-DD [awareness] …`。Q8 对第二写入者的答复是 yes *仅针对该推送器*。CCS Align 写入**席位自有**中间缓存，除非后续 PASS 明确指定其他路径。
5. **绝不写 `profile.md`、用户记忆或项目记忆。** 与 `GrokBotAwarenessPusher.ts`（`assertSafeAwarenessLogPath`）相同的硬规则。
6. **提示顶部无时钟。** 本机规则：时间戳属于事实，不属于破坏前缀缓存的头部。
7. **称呼 Alex，绝不 Az，** 在本工作新增的每个用户可见字符串中。
8. **不编辑 `CHANGELOG.md`**（自动生成）。若后续 `/do` 交付代码，changelog 任务会拾取。
9. **无新运行时依赖。** 复用 `fs` rename、现有 MCP/HTTP、现有设置加载器。
