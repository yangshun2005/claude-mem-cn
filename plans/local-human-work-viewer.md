# 本地人工工作查看器

## 主要目标
打开本地 claude-mem 查看器后，应能看到可理解的人工请求、已记录的进度，以及一个清晰的位置来审阅已完成的工作或接手交接任务。无需账号即可使用，可选的云连接入口指向现有设置流程。

## 阶段 0：文档调研
**如何服务于主要目标：** 在更改默认查看器之前，先确定实际的工作进程、数据、构建和连接 API。

阅读：src/services/worker/http/routes/ViewerRoutes.ts（现有 /、/stream、静态服务）；DatabaseManager.ts（getConnection）；request-auth-helpers.ts（isLocalhost、hasLoopbackHostHeader、hasForwardedClientHeaders）；src/shared/paths.ts（DB_PATH 和 DATA_DIR）；scripts/build-viewer.js（发布 UI 构建产物）；docs/public/cloud-sync.mdx（通过 cmem.ai Connect 和安装程序进行设置）。已验证的投影来源：云应用 apps/work-state-monitor/{data-source,agent-view,request-projection,view-model}；交互研究位于 design/live-interactions-v1。后端调研与实现委托给 audit_live_states，UI 集成委托给 ship_claude_mem。

允许的 API：Express 路由注册和 wrapHandler；Bun SQLite 只读 Database 及 prepare/get/all；本地提供的 EventSource 流；现有同步状态端点；现有 cmem.ai 设置链接。绝不为此视图添加本地原始工作写入或云调用。

## 阶段 1：本地数据与持久审阅
**如何服务于主要目标：** 实时工作以已保存的证据为依据；已检查意味着人工审阅了特定修订版本。

使用 Bun 只读适配器复制经过测试的投影。添加 /api/work-view 快照、SSE、证据和审阅路由。按请求标识和稳定的实质内容哈希存储私有本地审阅元数据。写入时校验预期哈希；更新的哈希需要重新审阅。保留源记录。使用现有中间件拒绝非回环请求和跨源变更。包含清晰的过期源健康状态。

验证：fixture SQLite 投影、通过 SSE 的真实写入、持久化的已检查/撤销和哈希失效、格式错误/过期载荷和来源拒绝。防护：不将心跳解释为代理活动；不做会话完成汇总；不暴露机密设置；不依赖生成副本推断。

## 阶段 2：默认面向人工的面板
**如何服务于主要目标：** 可读的默认页面让进度和人工后续操作可见，同时不隐藏熟悉的工具。

复制已批准的视觉研究外壳，移除虚构的模式/操作。通过 view-model 适配请求；就绪意味着明确报告完成，已检查意味着匹配持久化的审阅修订版本。保留原始请求/来源披露和已记录的更新。在阅读/滚动/聚焦时推迟传入重排序。保持已检查的撤销可用，并通过刷新处理 stale409。将本地连接健康状态与可选同步状态分开显示。在 /viewer 提供旧版查看器并带导航。将 Claude.ai 和 ChatGPT 链接到现有 Connect 设置，但不声称成功。

验证：已安装工作进程的 API/UI 冒烟测试、响应式浏览器检查、键盘对话框/焦点以及更新/已检查/重新加载/撤销流程。防护：不虚构分配/回复操作；不合成脉冲；不使用远程字体或必需的远程依赖。

## 阶段 2b：可选的 TeamBrain 共享工作区
**如何服务于主要目标：** 人们可以从个人工作转向团队的真实共享工作，同时不失去本地免费体验，也不混淆私有和共享记录。

阅读现有 `src/shared/teambrain.ts` 的成员资格、凭据和超时辅助函数；云 `src/lib/teambrain/{api,cli,work-state}.ts` 以了解确切的看板 Schema 和同意门控。在现有云同步身份、活动团队和成员资格检查之后，使用新的经过身份验证的只读 `GET /api/teambrain/cli/board?team_id=`。复用云 `teamBoard` 而不是复制其查询。本地路由仅暴露经过清理的状态和看板数据；凭据保留在工作进程中。不转发 Cookie，不自动共享。个人标签页不发起新的团队请求。TeamBoard 的开放列表/任务保持标记为共享工作，绝不转换为虚构的人工请求或本地已检查状态。

验证断开连接的无网络状态、实际 bearer/用户身份转发、看板载荷校验、权限失败清除、所选团队响应竞态、隐藏标签页轮询、阅读安全的待处理快照、确切的成员资格/项目范围、窄布局以及指向自助设置的有效链接。发布需等待云端点、TeamBrain UI 和 Stripe 购买路径由协调代理验证。

## 阶段 2c：限制项目重映射同步工作
**如何服务于主要目标：** 现有项目重映射必须可靠排空，之后人们才能依赖当前共享工作。

一项独立的实时同步调查发现，多个大型项目重映射被放在一个事务中发送。将每个 `remap_project` 放在各自有序的推送中发送，并在其前后刷新普通变更。保持正常的变更批处理和不可变的规范字节。传输失败必须让每个未确认的操作保持排队；只有序列化失败才属于隔离区。云 SQL 优化是单独的经审阅变更。

验证：263 个工作进程同步测试通过，包括混合普通/重映射顺序、已冻结的重映射、变更后的内容、重映射之前/期间的失败、精确字节重试和仅 ACK 删除。根 TypeScript/完整构建通过；独立审阅重新运行了 80 个 CloudSync 测试，无阻塞性发现。

## 阶段 3：审阅与完整发布
**如何服务于主要目标：** 用户通过正常的安装/更新渠道获得经过测试的本地功能。

独立代码审阅、相关测试和所有 CI；推送后立即打开 PR，照看讨论串，合并更新后的 main。在所有已记录的清单/徽章中应用所有者要求的 major14.0.0；构建并同步、打标签、GitHub 说明、生成变更日志、干净标签 npm 发布。现有损坏的 Discord webhook 是单独的已知后续事项，不重试。验证镜像仓库的精确/最新版本、包构建产物、隔离安装的 CLI 和全新工作进程 UI；观察 30 分钟并检查后期 CI/报告。

验证：干净的源/标签/包身份、默认和旧版路径、仅本地模式、审阅不修改源数据库、完整的 CI/审阅、干净的工作树。防护：不修改已发布的标签、不做出未经证实的发布声明、不输出令牌。

PR 审阅修正：SQLite `data_version` 观察其他连接对同一行的更新；哈希覆盖完整的关联源证据，而不向实时载荷添加原始文本；生命周期选择携带规范的时间/设备/来源行顺序，包括大于 2^53 的 ID；新应用的 TeamBrain 快照会清除任何更早的待处理快照。独立路由和 DOM 回归测试以及合并的 163 项测试产品套件通过。仅同步时间的变化保留匹配的人工检查。

最终真实数据修正：显式的 needs-input/waiting-on-user/approval 别名共享已记录子状态所使用的现有 Needs you 映射。未知生命周期值保留先前的回退。原始目标和下一步保持不变。扩展的 170 项测试产品套件和只读实时数据投影检查通过。

完整 Linux CI 运行了 9,506 项测试，9,446 项通过，58 项跳过；仅有的 2 项失败是新的路由集成防护。该路由现在记录成功的审阅变更而不含源内容，并在使用共享 IPv6 格式化器之前校验回环权威。同端口 IPv6 和格式错误权威的回归测试通过。扩展的产品/路由/质量套件：175 项通过。仍需全新的完整 CI。
