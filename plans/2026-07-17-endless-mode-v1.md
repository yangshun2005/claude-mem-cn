## 1. 问题

当 Claude Code 会话运行足够久时，harness 会执行**压缩（compaction）**：把对话总结成几段话，丢弃原始上下文，只以该摘要作为模型对之前一切的唯一记忆继续运行。会话存活了，记忆没有。压缩之后，模型丢失了它的计划、它的确切措辞、它对已尝试过什么的认识——用户感受到的是助手在会话中途变笨了。

摘要由 Claude Code 生成，插件无法替换或抑制。但插件*可以*在恰当时机注入额外上下文，而 claude-mem 已经存储了重建会话所需的一切，且远比任何摘要忠实。

## 2. 一切所依赖的关键事实

**压缩只破坏上下文窗口。** 会话的两份持久记录留在磁盘上，未被触碰：

1. **转录文件（transcript）。** Claude Code 把会话的每个事件——用户消息、助手消息、工具调用、工具结果——追加到 `~/.claude/projects/<dashed-project-path>/<sessionId>.jsonl` 的 JSONL 文件。压缩不会截断或删除它。
2. **claude-mem 的数据库。** 观察记录、用户提示和会话摘要，由 Hook 和 worker 实时捕获。

所以压缩*之前*什么都不需要做。没有状态需要抢救。当新上下文开始时，我们从磁盘重建会话记录，并把指向它的指针交给模型。

## 3. 功能

**Endless Mode**：在每个压缩后（或恢复）上下文开始时，claude-mem 写一个 markdown 文件——**bottle**——重建会话，并注入一条简短指令：*读取此文件并继续*。

bottle 是：

```
bottle = merge( transcript.jsonl , claude-mem observations )
```

- **用户和助手消息：逐字**，来自转录文件。在典型编码会话中，这些只占约 5–20% 的 token。
- **工具调用和工具结果：省略**，替换为 claude-mem 从中生成的**观察记录**。工具流量占会话 token 的 80–95%，而观察记录正是其压缩后的、人类可读的形式——压缩已在会话进行时实时完成。

结果：会话记录比真实上下文小约 10–20 倍，对话主干逐字保留。模型从自己的最后话语继续，而不是从转述继续。

bottle 是**派生的，从不维护**：两个来源的纯函数，按需整体重新生成，原子写入。磁盘上的文件是缓存，不是事实来源。没有 Hook 向它追加；没有任何东西会漂移。

## 4. 机制入门（实现者需要知道的）

**Claude Code Hook。** 插件为生命周期事件注册处理器。每个 Hook 是一个子进程，从 stdin 接收 JSON 载荷，可向 stdout 输出 JSON 响应。相关事件：

- `SessionStart` — 上下文开始时触发，`source` = `"startup"`（全新会话）、`"compact"`（压缩刚结束，同一 `session_id`）、`"resume"`（用户重新打开会话）或 `"clear"`（用户运行 `/clear`）。载荷含 `session_id`、`transcript_path`、`cwd`。Hook 通过打印以下内容注入上下文：
  `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "<text>"}}`
- `Stop` — 每个助手回合结束时触发。claude-mem 现有的 Stop 处理器（`src/cli/handlers/summarize.ts`）已在每次 Stop 时读取完整转录文件，所以每回合全量读取转录是既定的成本基线。
- Hook 绝不能破坏会话：吞掉错误，传输失败时以 0 退出（`src/cli/hook-command.ts` 中的既有约定）。

**claude-mem 存储**（SQLite，`~/.claude-mem/claude-mem.db`）：

- `sdk_sessions` — 每个 Claude Code 会话一行，以 `content_session_id` 为键（Claude Code 的会话 id——跨压缩稳定）。持有当前 `memory_session_id`；`observations` 和 `session_summaries` 的外键在更新时级联，所以**一次 join 即可到达一切**，无论 worker 是否重启：
  `content_session_id → sdk_sessions → memory_session_id → observations + session_summaries`
- `observations` — 由 worker 的 SDK agent 从工具活动异步生成的有类型记录（标题、叙述、事实、文件、概念）。每条携带 **`prompt_number`**——它发生在哪个用户提示下——以及已锚定到工具时间的时戳。
- `user_prompts` — 每个用户提示，**逐字**（上限 4,000 字符，约 3.5% 的提示触及上限），以 `content_session_id` 和 `prompt_number` 为键。
- `session_summaries` — LLM 生成的每回合摘要（`request/investigated/learned/completed/next_steps/notes`）。唯一比转录文件存续更久的助手视角记录——但是生成的散文，**不是**助手的话语。

**worker** 是本地 Express 守护进程，拥有数据库和 SDK agent。路由位于 `src/services/worker/http/routes/`，继承 `BaseRouteHandler`，通过构造函数注入获取服务，在 `worker-service.ts` 中注册。长任务遵循排队即返回的形态：立即响应，异步执行，失败记为非阻塞日志。

**隐私契约。** claude-mem 持久化的每段文本都经过 `stripMemoryTags`（`src/utils/tag-stripping.ts`），它移除 `<private>` 标记的内容和宿主注入的噪声。任何把对话文本写入磁盘的新路径都必须同样处理。

**转录保留。** Claude Code 会清理旧转录文件（默认约 30 天）。在典型长期安装中，*大多数*已存储会话不再有转录文件——但它们的提示、观察记录和摘要仍在 SQLite 中存续。渲染器必须处理两种情况（§6）。

## 5. 要构建什么

四部分。其中一个是可选的。

### 5.1 `BottleRenderer`（新 worker 服务）

输入：`contentSessionId`，可选 `transcriptPath`。输出：bottle 文件，原子写入（写临时同级文件，`rename()` 覆盖目标——先例见 `src/shared/atomic-json.ts`）。

- 文件位置：`~/.claude-mem/bottles/<contentSessionId>.md`；`/clear` 时归档到 `~/.claude-mem/bottles/archive/<ts>-<id>.md`。
- 每次渲染解析整个转录文件（无增量游标——见 §8）。从**助手**条目只保留文本块（跳过 `tool_use`、`tool_result`、thinking）。从**用户**条目只保留真实消息（跳过工具结果和注入信封，如 `<system-reminder>`、`<task-notification>`、命令包装）。跳过被截断的最后一行——文件正在被实时追加。
- 通过单次 `sdk_sessions` join 获取观察记录和摘要。按 `prompt_number` 定位观察记录（归组到它们所属的用户提示下），组内按 `created_at_epoch` 排序。
- **对每条渲染的消息应用 `stripMemoryTags`。** 硬性要求——逐字渲染是唯一否则会绕过隐私契约的路径。

**降级模式——转录文件缺失。** 用 `existsSync(transcriptPath)` 检测；未提供路径时，尝试约定 glob `CLAUDE_CONFIG_DIR/projects/*/<contentSessionId>.jsonl`（该约定已在 `src/services/context/ObservationCompiler.ts` 中固化）。若转录文件已不存在，仅从 SQLite 渲染：

- `user_prompts` → 逐字用户消息。触及 4,000 字符上限的提示加显式 `[truncated at 4000 chars]` 标记。
- `observations` → 同样的单行条目，按 `prompt_number` 定位。
- `session_summaries` → 渲染为明显是生成的块：
  `> Session summary (generated by claude-mem — not verbatim)`
  **绝不**渲染在 `**Assistant**` 标题下。摘要散文读起来像助手口吻；把它放进助手嘴里，恢复后的模型会"记得"说过它从未说过的话。
- 头部行声明模式：`mode: reconstructed — assistant messages not preserved`。
- 没有转录文件，助手消息就是无法恢复——claude-mem 中没有任何东西原样持久化它们。不要伪造。

若会话既无转录文件也无任何已存储的提示/观察记录，渲染器报告失败，Hook 回退到当前行为（§5.3）。

### 5.2 `POST /api/sessions/render-bottle`（新 worker 路由）

Body：`{ contentSessionId, transcript_path?, wait? }`。

- 默认：排队即返回——立即响应 `{status:"queued"}`，异步渲染，`.catch()` → 非阻塞错误日志。
- `wait: true`：同步渲染，响应 `{ bottlePath, mode }`。SessionStart 用这个——文件必须在指针注入前存在。

### 5.3 SessionStart Hook——按 `source` 分支

- **`compact` / `resume`：** 以 `wait: true` 调用 `render-bottle`（约 10s 超时）。成功则注入指针块（§7）。任何失败——worker 宕机、渲染错误、无可渲染内容——则完全按今天的方式注入现有时间线上下文。**Endless Mode 绝不能使用户处境比当前行为更差。**
- **`clear`：** 归档 bottle，不注入任何内容。`/clear` 意味着用户要求遗忘。
- **`startup`：** 不变。

无记账表、无一次性消费状态：注入是指向幂等文件的指针。若 SessionStart 双重触发（可能发生），模型会两次收到同样的 20 行——无害。

### 5.4 可选：Stop 时渲染

在 Stop 处理器（`summarize.ts`）中，现有 summarize 调用之后：

```ts
try {
  await executeWithWorkerFallback('/api/sessions/render-bottle', 'POST',
    { contentSessionId, transcript_path }, { timeoutMs: 5000 });
} catch { /* never escalate */ }
```

**要 await 它**——Hook 进程会调用 `process.exit`，这会杀死飞行中的未 await 请求（`hook-command.ts` 中有记录）。这使磁盘上始终有一份实时、人类可读的会话日记。锦上添花；正确性不依赖它。

## 6. bottle 格式

```markdown
# Session bottle — <contentSessionId>
project: <cwd> · started: <ts> · rendered: <ts>
mode: full

## Original request
<first genuine user prompt, verbatim>

---
**User** (10:32)
<verbatim>

*What happened:*
- [#102401] Explored hooks/ — every platform hook wraps 5 shared cores
- [#102402] Read start.mjs — 6 self-heal layers before MCP boot

**Assistant** (10:41)
<verbatim>
---
```

- 观察记录行保持单行：`[#id] title — first clause of narrative`。id 使任何行可通过 claude-mem 的搜索工具展开；绝不内联完整叙述。
- 消息逐字且不截断。压缩刚释放了数十万 token；一份花费几千 token 的忠实记录正是重点。

## 7. 注入内容

完整模式：

```
# [claude-mem] Endless Mode — session continuation

Before doing anything else, Read this file and continue the session from
where it ends:

    <absolute bottle path>

- It is the authoritative session record: verbatim conversation, with
  observations in place of tool activity. Where it conflicts with the
  summary above, the bottle wins.
- The final assistant message in it was already delivered to the user.
  Do not repeat it or redo work it describes as done — continue from its
  end state.
- The newest tool activity may still be settling into observations;
  check the timeline if the last few minutes look thin.

Current task: <one line, from the latest session summary or last user prompt>
```

降级模式替换中间几条：

```
- It is a partial reconstruction: only the user's messages are verbatim.
  Your own replies were not preserved — do not assume prior phrasings.
  Session summary blocks are generated, not your words.
- The last session summary describes where you left off; continue from there.
```

重要说明：

- **是指针，不是载荷。** 注入约 20 行；模型通过 `Read` 拉取 bottle，作为工具结果落入上下文——正是*下一次*压缩最先驱逐的类别。bottle 从不跨压缩累积；每个新上下文重新读取。
- **"不要重复"那行是关键承重。** 没有它，模型会可靠地重发最后一条消息或重做已完成的工作。
- "Current task" 行是为少数跳过 Read 的上下文上的保险。

## 8. 刻意不构建

| 不构建 | 原因 |
|---|---|
| PreCompact Hook，或任何"擦除前捕获"步骤 | 来源（转录文件、数据库）在压缩后存续；没有东西需要抢救。在 SessionStart 惰性渲染。 |
| 渲染前等待观察队列排空 | 观察记录异步生成，最新的工具事件可能还没有对应观察——没关系。逐字的最后助手消息覆盖尾部叙述，注入带一行免责声明，任何后续渲染都会包含它们。阻塞在 LLM 支撑的队列上几乎买不到什么。 |
| bottle 状态表 / 一次性注入标记 | 文件就是状态；注入是幂等指针。 |
| 增量转录解析（字节游标）+ 渲染互斥锁 | Stop Hook 今天已每回合读取完整转录文件。每次渲染全量重解析与基线一致；渲染是来源的纯函数，所以并发渲染是同等有效内容的最后写入者胜出。 |
| 新 schema 列（工具调用锚点、`tool_use_id` 串联） | `prompt_number`——已在 `user_prompts` 和 `observations` 上——精确定位一切。若将来需要按工具调用定位，下次 schema 升级时再议。 |

## 9. 测试

1. **回合中途压缩：** 转录文件以未完成回合结尾 → bottle 逐字包含该回合的助手文本。
2. **隐私：** 用户和助手消息中的 `<private>` 内容 → 在每条渲染路径上都不出现在 bottle 中。
3. **降级渲染：** 删除一个有提示/观察记录/摘要的会话的转录文件 → `mode: reconstructed` 头部、`prompt_number` 排序、摘要作为引用的生成块（绝不在 `**Assistant**` 下）、截断标记存在。
4. **SessionStart(compact) 时 worker 宕机：** Hook 以 0 退出并注入今天的时间线上下文。
5. **`/clear`：** bottle 归档，不注入任何内容。
6. **双重 SessionStart(compact)：** 两次相同的指针注入，无损坏（接受的行为）。
7. **端到端：** 驱动真实会话越过自动压缩；验证模型读取 bottle、继续工作且不重复其最后消息。

## 10. 后续（v2 候选）

- `npx claude-mem bottle <contentSessionId>` — 渲染任何历史会话并在新上下文中恢复它（降级路径已使转录文件早已不存在的会话成为可能）。
- 为 bottle 变得不适用的马拉松会话做分段汇总（把最旧的一段折叠为仅观察 id——按引用无损，因为完整内容仍在数据库中）。
- 按工具调用的观察锚定（`tool_use_id` 串联、锚点列）。
- Stop 时渲染的服务器运行时对齐（当前 Stop 处理器的服务器分支提前返回）。
