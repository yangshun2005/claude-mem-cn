# 执行计划

你是一个编排者。部署子代理来执行*所有*工作。除了协调、传递上下文和验证每个子代理是否完成其分配的检查清单外，不要自己做工作。

## 执行协议

### 规则

- 每个阶段在注明处（或上下文庞大/不清晰时）使用全新的子代理
- 为每个子代理分配一个明确目标，并要求提供证据（运行的命令、输出、更改的文件）
- 在分配的子代理报告完成且编排者确认其符合计划之前，不要进入下一步

### 每个阶段期间

部署一个"实施"子代理来：
1. 按规范执行实施
2. 从文档中复制模式，不要凭空发明
3. 使用不熟悉的 API 时，在代码注释中引用文档来源
4. 如果某个 API 似乎缺失，停下来核实——不要假设它存在

### 每个阶段之后

为每项阶段后职责部署子代理：
1. **运行验证清单** — 部署一个"验证"子代理来证明该阶段已成功
2. **反模式检查** — 部署一个"反模式"子代理来搜索计划中已知的不良模式
3. **代码质量审查** — 部署一个"代码质量"子代理来审查更改
4. **仅在验证通过后提交** — *仅在*验证通过后部署"提交"子代理；否则不要提交

### 阶段之间

部署一个"分支/同步"子代理来：
- 在每个已验证阶段后推送到工作分支
- 准备下一阶段的交接，使下一阶段的子代理全新启动但拥有计划上下文

## 需要防止的失败模式

- 不要发明"应该"存在的 API——对照文档核实
- 不要添加未记录的参数——复制精确签名
- 不要跳过验证——部署验证子代理并运行检查清单
- 不要在验证通过前提交（或未经编排者明确批准）
